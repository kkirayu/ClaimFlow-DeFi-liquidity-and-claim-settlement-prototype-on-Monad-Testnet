# Deployment guide

ClaimFlow deploys three contracts and configures roles. There is no backend and no database.

| Contract         | Purpose                                                          |
| ---------------- | ---------------------------------------------------------------- |
| `MockUSDC`       | 6-decimal demo token with a capped faucet                        |
| `LiquidityVault` | Deposits, shares, reserved/available accounting, payouts         |
| `ClaimManager`   | Claim lifecycle, roles, atomic approval, single/batch settlement |

## Prerequisites

- Node.js 22+, pnpm 12, Foundry (`forge`, `anvil`, `cast`)
- For testnet: a dedicated funded wallet on Monad Testnet
  (`https://faucet.monad.xyz`)

## Local deployment

### One command

```bash
pnpm install
pnpm dev:local
```

The script:

1. Starts Anvil on `127.0.0.1:8545` (chain ID `31337`) if no node is reachable.
2. Builds the contracts and regenerates the frontend ABIs.
3. Deploys the three contracts with the public Anvil account #0.
4. Grants all roles, enables self-approval (local demo), seeds liquidity and five claims.
5. Writes `deployments/31337.json` and `frontend/.env.local`.
6. Starts Vite on <http://localhost:5173>.

The process keeps Anvil alive only if the script started it. `Ctrl+C` cleans up.

### Manual steps

```bash
# terminal 1
pnpm anvil

# terminal 2
pnpm contracts:build
pnpm sync:abis
pnpm deploy:local
pnpm dev
```

### Resetting the demo

Stop Anvil, then run `pnpm dev:local` again. A fresh chain produces a fresh deployment. Old
`frontend/.env.local` addresses are overwritten; `deployments/31337.json` is replaced.

## Monad Testnet deployment

### 1. Prepare the key

Use a **dedicated testnet wallet**. Never reuse a mainnet key.

```bash
cp .env.example .env
```

Set at minimum:

```dotenv
PRIVATE_KEY=0x...                       # dedicated, funded testnet key
ALLOW_SELF_APPROVAL=false               # default for non-local networks
MAX_BATCH_SIZE=20
```

Optional separation of duties:

```dotenv
CLAIM_OPERATOR_ADDRESS=0x...
CLAIM_APPROVER_ADDRESS=0x...
SETTLEMENT_ADDRESS=0x...
CLAIM_CANCELLER_ADDRESS=0x...
```

If omitted, the deployer receives each role. With `ALLOW_SELF_APPROVAL=false`, the operator and
approver must be different wallets for a complete single-claim demo.

### 2. Deploy

```bash
pnpm contracts:build
pnpm deploy:testnet
```

The script:

- Verifies the RPC chain ID is `10143` before sending anything.
- Refuses to deploy when the deployer balance is zero.
- Deploys `MockUSDC`, `LiquidityVault`, and `ClaimManager`.
- Grants `CLAIM_MANAGER_ROLE` to the manager on the vault and the four operator roles on the manager.
- Enables self-approval only if explicitly configured.
- Writes `deployments/10143.json` and `frontend/.env.local`.
- Prints the explorer base URL; it never prints the private key.

### 3. Seed optional demo data

```bash
pnpm seed:testnet
```

The seed requires the deployer to hold the minter/operator/approver roles and enough testnet gas. It
deposits demo liquidity, mints faucet tokens, and creates five synthetic claims (pending, approved,
paid, rejected).

### 4. Build and host

```bash
pnpm build
pnpm preview
```

`frontend/dist` is a static SPA. Configure the host to serve `index.html` for unknown paths.

### 5. Verify

- The Protocol page lists the deployed addresses and chain ID `10143`.
- The header shows `Monad Testnet`.
- A wallet can request faucet tokens once per hour.
- A deposit produces shares and updates available/reserved metrics.
- A claim can be submitted, approved (reservation), and settled once.
- Batch settlement reverts if any selected claim is invalid.
- Explorer links point at `https://testnet.monadscan.com`.

## Environment precedence

Deployment scripts load `.env` and then `.env.local` from the repository root, then read process
environment variables. `frontend/.env.local` is generated by the deploy script and is gitignored.

## Network facts

| Network       | Chain ID | RPC                             | Explorer                        |
| ------------- | -------- | ------------------------------- | ------------------------------- |
| Monad Testnet | `10143`  | `https://testnet-rpc.monad.xyz` | `https://testnet.monadscan.com` |
| Anvil local   | `31337`  | `http://127.0.0.1:8545`         | Not available                   |

Testnet information can change or reset. Re-check the official Monad documentation before
deploying.

## Troubleshooting

| Symptom                                    | Cause / fix                                                                            |
| ------------------------------------------ | -------------------------------------------------------------------------------------- |
| `Missing contract artifact`                | Run `pnpm contracts:build` first.                                                      |
| `RPC chain id ... does not match`          | Wrong `LOCAL_RPC_URL` / `MONAD_RPC_URL`, or a stale Anvil process.                     |
| `The deployer has 0 MON`                   | Fund the testnet wallet from the Monad faucet.                                         |
| App shows the configuration gate           | `frontend/.env.local` is missing or addresses are invalid. Re-run `pnpm deploy:local`. |
| Wallet on wrong network                    | Use the in-app “Switch network” action or add chain `31337` / `10143` manually.        |
| Faucet cooldown                            | Per-address cooldown is one hour and the lifetime cap is 500,000 mUSDC.                |
| Approval fails with self-approval disabled | Use a different approver wallet, or enable the flag only on a local demo deployment.   |
| Batch settlement fails                     | Every selected claim must still be `Approved & Reserved`; the batch is atomic.         |
| E2E cannot connect                         | Start Anvil and `pnpm deploy:local` first; tests skip when RPC is unavailable.         |
| No explorer links locally                  | Expected: Anvil has no block explorer and the UI hides dead links.                     |

## Safety

- Only testnet funds and mock tokens.
- Do not commit `.env`, `frontend/.env.local`, `deployments/*.json`, or private keys.
- Contracts are unaudited; a production deployment requires an independent audit, key management,
  monitoring, and a legal/compliance review.
